# Database

Eurus uses PostgreSQL as its persistent data store, accessed through Prisma ORM. The database schema is defined in `prisma/schema.prisma` and managed through Prisma migrations.

## Schema Overview

The database consists of 7 models that manage users, rooms, membership, messages, invites, encryption keys, and device registrations.

```
┌──────────┐     ┌──────────┐     ┌──────────────┐
│  User    │────<│  Room    │────<│  RoomMember  │
│          │     │          │     └──────────────┘
│          │     │          │     ┌──────────────┐
│          │────<│          │────<│  RoomKey     │
│          │     │          │     └──────────────┘
│          │     │          │     ┌──────────────┐
│          │────<│          │────<│  RoomInvite  │
│          │     │          │     └──────────────┘
│          │     │          │     ┌──────────────┐
│          │────<│          │────<│  Message     │
│          │     └──────────┘     └──────────────┘
│          │
│          │     ┌──────────┐
│          │────<│  Device  │
└──────────┘     └──────────┘
```

## Models

### User

The central identity model. Each user has a unique username and one or more public keys for authentication.

| Field | Type | Description |
|---|---|---|
| `id` | UUID (PK) | Unique identifier |
| `username` | String (unique) | Display name, 3-32 chars, alphanumeric + `_` `-` |
| `publicKeyEd25519` | String? | Ed25519 public key (base64) |
| `publicKeyRsa` | String? | RSA public key (PEM) |
| `createdAt` | DateTime | Account creation time |
| `lastSeen` | DateTime | Last authentication time |

**Relations:**
- `createdRooms` — Rooms this user created (one-to-many)
- `roomMemberships` — Rooms this user is a member of (many-to-many via `RoomMember`)
- `messages` — Messages sent by this user (one-to-many)
- `devices` — Registered devices (one-to-many)
- `createdInvites` — Invite codes generated by this user (one-to-many)

### Room

Chat rooms with human-readable names and type-based visibility.

| Field | Type | Description |
|---|---|---|
| `id` | UUID (PK) | Unique identifier |
| `name` | String (unique) | URL-safe identifier (e.g., `"general"`) |
| `displayName` | String | Human-readable name (e.g., `"#general"`) |
| `roomType` | Enum | `"public"`, `"private"`, or `"dm"` |
| `encryptedKey` | String | Server-managed AES-256 room encryption key |
| `creatorId` | UUID (FK) | Room owner (references `User.id`) |
| `createdAt` | DateTime | Room creation time |
| `deletedAt` | DateTime? | Soft-delete timestamp |

**Relations:**
- `creator` — The user who created the room
- `members` — Users who are members (many-to-many via `RoomMember`)
- `messages` — Messages in this room (one-to-many)
- `roomKeys` — Per-user encrypted keys (one-to-many)
- `invites` — Active invite codes (one-to-many)

### RoomMember

Join table tracking room membership. Uses a composite primary key.

| Field | Type | Description |
|---|---|---|
| `roomId` | UUID (PK) | References `Room.id` |
| `userId` | UUID (PK) | References `User.id` |
| `joinedAt` | DateTime | When the user joined |

**Composite primary key:** `[roomId, userId]`

This model is intentionally simple — it tracks who *can* access a room, not who is currently connected. Connection state is managed in-memory by the server.

### RoomInvite

Single-use, time-limited invite codes for private rooms.

| Field | Type | Description |
|---|---|---|
| `code` | String (unique, PK) | 8-character alphanumeric code |
| `roomId` | UUID (FK) | Target room |
| `createdById` | UUID (FK) | User who generated the code |
| `createdAt` | DateTime | Generation time |
| `expiresAt` | DateTime | Expiry time (24 hours from creation) |
| `usedById` | UUID? | User who used the code (null if unused) |
| `usedAt` | DateTime? | When the code was used |

**Validation rules:**
- Code must not be expired (`expiresAt > now`)
- Code must not be already used (`usedById` is null)
- Room must not be deleted

### RoomKey

Per-user encrypted room keys for secure key distribution.

| Field | Type | Description |
|---|---|---|
| `roomId` | UUID (PK) | References `Room.id` |
| `userId` | UUID (PK) | References `User.id` |
| `encryptedKey` | String | Room's AES key, encrypted for this user |

**Composite unique key:** `[roomId, userId]`

Each user in a room has their own `RoomKey` entry. The `encryptedKey` is the room's AES-256 key encrypted specifically for that user, ensuring that only the intended recipient can decrypt it.

### Message

Encrypted chat messages.

| Field | Type | Description |
|---|---|---|
| `id` | UUID (PK) | Unique identifier |
| `roomId` | UUID (FK) | Target room |
| `senderId` | UUID (FK) | Message author |
| `ciphertext` | String | AES-256-GCM encrypted content (hex-encoded) |
| `messageType` | Enum | `"text"` or `"image"` |
| `imageUrl` | String? | Object storage URL (for image messages) |
| `createdAt` | DateTime | Message timestamp |

**Composite index:** `[roomId, createdAt]` — Optimizes message history queries with cursor-based pagination.

Messages are stored as ciphertext. The server never sees plaintext content.

### Device

Registered devices per user for multi-device support.

| Field | Type | Description |
|---|---|---|
| `id` | UUID (PK) | Unique identifier |
| `userId` | UUID (FK) | Owner |
| `deviceName` | String | Human-readable device name |
| `publicKey` | String | Device-specific public key |
| `lastUsed` | DateTime | Last authentication from this device |
| `createdAt` | DateTime | Registration time |

## Migrations

### Running Migrations

```bash
# Generate a new migration from schema changes
npx prisma migrate dev --name <description>

# Deploy migrations to production
npx prisma migrate deploy

# Generate the Prisma client
npx prisma generate
```

### Seeding

The `seed.ts` script creates test data for development:

```bash
npx prisma db seed
```

This creates:
- 3 test users: `alice`, `bob`, `charlie`
- 3 rooms: `general` (public), `random` (public), `project-alpha` (private)
- Sample messages and memberships

## Database Connection

The Prisma client is initialized as a singleton in `src/database.ts`:

```typescript
import { PrismaClient } from '@prisma/client';

const globalForPrisma = globalThis as unknown as { prisma: PrismaClient };

export const prisma = globalForPrisma.prisma || new PrismaClient({
  log: process.env.NODE_ENV === 'development' ? ['query', 'error', 'warn'] : ['error'],
});

if (process.env.NODE_ENV !== 'production') globalForPrisma.prisma = prisma;
```

The connection string is read from the `DATABASE_URL` environment variable. On graceful shutdown, `prisma.$disconnect()` is called to close the connection pool.
